# Enhancing Maritime Safety

GitHub Pages microsite for EPSRC project EP/X035778/1.

Live site: https://stereoocean.github.io/

This site is intentionally high level while project outputs are in preparation. It should describe the public project context and publication roadmap, not unpublished implementation details, results, datasets, model names, internal repositories, or draft paper content.

## Content Rules

- Keep output descriptions public-facing and high level until papers, datasets, or supporting materials are cleared for release.
- Do not publish internal source notes, private repository links, unpublished methods, unpublished metrics, or draft manuscript details.
- Put unpublished working material in `reference_material/`; that directory is excluded from the generated site.
- Do not edit `_site/` directly. It is generated by Jekyll and excluded from publication.
- Partner and funder logos need permission from the relevant organisation before being committed. The current repo only includes the University of Portsmouth logo.

## Quick Editing Guide

For small copy, data, or image updates, it is fine to edit files directly on GitHub. For layout, style, or larger edits, use a local preview before publishing; see [Developer Notes](#developer-notes).

| To change | Edit |
| --- | --- |
| Homepage hero text or body copy | `index.md` |
| Team page heading or intro copy | `team.md` |

## Editing On GitHub

Use this route for straightforward content updates.

1. Open the repository at `https://github.com/stereoocean/stereoocean.github.io`.
2. Click the file you want to edit. Use the table above to choose the file.
3. Look for the pencil icon near the top-right of the file view. GitHub labels it `Edit this file`.
4. Make the change in the browser editor.
5. Use the `Preview` tab to check Markdown formatting when editing `.md` files.
6. Click the green `Commit changes...` button.
7. Add a short commit message, such as `Update team page copy`.
8. Choose `Commit directly to the main branch` only for simple, approved content changes. Otherwise choose `Create a new branch for this commit and start a pull request`.

To add a new file on GitHub, open the target folder, then use `Add file` > `Create new file` or `Upload files`.

## Editing Content

### Homepage

Edit `index.md`.

The top front matter controls page metadata and hero text:

```yaml
layout: home
nav_key: home
title: Enhancing Maritime Safety
description: Developing accessible real-time semantic wave imaging methods to support safer seakeeping decisions.
grant_line: EPSRC project EP/X035778/1 | University of Portsmouth
hero_title: Enhancing Maritime Safety
hero_subtitle: Developing an accessible real-time semantic wave imaging analyser for seakeeping
```

The markdown below the front matter controls the visible body copy on the homepage.

### Standard Pages

Edit an existing standard page by changing its markdown file, such as `team.md` or `partners.md`.

Creating a new non-output page usually also needs navigation or layout work; see [Developer Notes](#developer-notes).

### Output Pages

Output pages live in `_outputs/`. Add a new output by creating a new markdown file there, for example `_outputs/new-output.md`.

Use this front matter pattern:

```yaml
---
title: New Output
lead: Output lead or owner
status: Manuscript in preparation
image: /assets/img/outputs/new-output.svg
order: 4
description: Short public summary for metadata and cards.
---
```

Then write the public-facing page body below the front matter. The homepage output grid is generated from these files, ordered by `order`.

Required output fields are `title`, `lead`, `status`, `image`, `order`, and `description`. Add the referenced image to `assets/img/outputs/`.

### Team Members

Edit `_data/team.yml` for team members. Edit `team.md` for the team page heading or intro copy.

Use this pattern:

```yaml
- name: Jane Smith
  role: Project role
  profile: "https://example.com/profile"
  image: /assets/img/team/jane-smith.jpg
  initials: JS
```

Required team fields are `name`, `role`, `profile`, and `initials`. `image` is optional. If it is omitted, the site uses `initials` as a fallback avatar.

Add team photos to `assets/img/team/`. Prefer clear portrait images with simple lowercase, hyphenated filenames.

### Partners

Edit `_data/partners.yml` for partner cards. Edit `partners.md` for the partners page heading or intro copy.

Use this pattern for text-only partner cards:

```yaml
- name: Example Organisation
  short_name: Example Org
  url: https://example.org/
```

Use this pattern only when logo permission is confirmed:

```yaml
- name: Example Organisation
  short_name: Example Org
  url: https://example.org/
  logo: /assets/img/partners/example-org.svg
  logo_alt: Example Organisation
```

Add approved logos to `assets/img/partners/`. If this repo gets an open-source license later, partner logos should be explicitly excluded from that license.

Required partner fields are `name`, `short_name`, and `url`. `logo` and `logo_alt` are optional and should only be used when logo permission is confirmed.

### Hero Image

The current hero image is:

```text
assets/img/hero/hero-wave-imaging.png
```

To replace it without changing CSS, overwrite that file with another image using the same filename. If you rename it, update both `hero-wave-imaging.png` references in `assets/css/site.css`.

## Publishing

The production site is served by GitHub Pages from:

```text
https://github.com/stereoocean/stereoocean.github.io
```

GitHub Pages is configured to publish from:

```text
branch: main
folder: /
```

GitHub Pages will build and deploy automatically after changes are committed to `main`. The live site is:

```text
https://stereoocean.github.io/
```

GitHub's CDN can cache assets briefly. If a newly pushed image does not appear immediately, wait a few minutes and refresh.

## Developer Notes

Use these notes for local development, layout changes, styling changes, and command-line publishing.

### Local Preview

Use a current Ruby installation rather than macOS system Ruby.

```bash
bundle install
PAGES_REPO_NWO=stereoocean/stereoocean.github.io bundle exec jekyll serve --host 127.0.0.1 --port 4000
```

Then open:

```text
http://127.0.0.1:4000/
```

For a one-off build check:

```bash
PAGES_REPO_NWO=stereoocean/stereoocean.github.io bundle exec jekyll build
```

### Repository Structure

- `index.md` contains homepage front matter and editable homepage copy.
- `team.md` and `partners.md` contain the main markdown copy for those pages.
- `_outputs/` contains markdown-backed output pages. These also feed the homepage output cards.
- `_data/team.yml` contains reusable team-member data.
- `_data/partners.yml` contains reusable partner/funder data.
- `_includes/` contains shared renderers such as output cards, the team grid, and the partner list.
- `_layouts/` contains page shells and structure.
- `assets/css/site.css` contains the site styling.
- `assets/img/hero/` contains the homepage and page-header image.
- `assets/img/team/`, `assets/img/outputs/`, and `assets/img/partners/` contain images grouped by use.

### Navigation, Layout, And Styling

Main navigation lives in `_includes/nav.html`. Site styling lives in `assets/css/site.css`.

Only edit `_layouts/` or `_includes/` when changing shared page structure. For normal content updates, edit markdown files or YAML data instead.

### Standard Page Creation

Use this front matter pattern when creating a new standard page:

```yaml
---
layout: page
nav_key: page-key
title: Page Title
description: Short page summary for metadata.
permalink: /page-url/
---
```

Write the visible page content below the front matter. To link a new page from the main navigation, add it to `_includes/nav.html` and use the same `nav_key` value for the active-page state.

### Command-Line Publishing

To publish from a local checkout:

```bash
git status
git add <changed files>
git commit -m "Describe the change"
git push
```

GitHub Pages will build and deploy automatically after `main` is pushed.
